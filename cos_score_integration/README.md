# COS Integration

This folder contains the COS Phase 1 test data and integration with the main FReD pipeline.

## Overview

The COS (Collaborative Open Science) test data can optionally be merged with the main FReD dataset during preparation. This is controlled by an environment variable toggle, making it easy to enable or disable COS data merging as needed.

## Files

- **cos_test_set_phase1.csv** - Raw COS Phase 1 test data
- **cos_test_set_phase1_prepared.xlsx** - Prepared COS data (generated by prepare_cos_data.R)
- **prepare_cos_data.R** - Script to prepare COS data for merging with FReD

## Enabling COS Integration

COS data merging is controlled by the `ENABLE_COS_MERGE` environment variable.

### Option 1: Set environment variable (recommended)

```bash
# Enable COS merging
export ENABLE_COS_MERGE=TRUE

# Run FReD preparation pipeline
quarto render pipelines/fred/prepare_fred.qmd

# Disable COS merging
export ENABLE_COS_MERGE=FALSE
```

### Option 2: Edit .env file

1. Copy `.env.example` to `.env` (if not already done):
   ```bash
   cp .env.example .env
   ```

2. Edit `.env` and set:
   ```
   ENABLE_COS_MERGE=TRUE
   ```

3. Load environment from .env:
   ```bash
   set -a; source .env; set +a
   quarto render pipelines/fred/prepare_fred.qmd
   ```

## Preparing COS Data

Before enabling COS integration, you may need to prepare the COS data by running:

```bash
Rscript cos_integration/prepare_cos_data.R
```

This script:
1. Reads `cos_test_set_phase1.csv`
2. Standardizes column names and values to match FReD format
3. Saves prepared data to `cos_test_set_phase1_prepared.xlsx`

## How It Works

When `ENABLE_COS_MERGE=TRUE`:

1. The `pipelines/fred/prepare_fred.qmd` pipeline downloads main FReD data
2. Checks for `cos_integration/cos_test_set_phase1_prepared.xlsx`
3. Merges COS data with FReD using common columns
4. Both datasets are then cleaned, validated, and augmented together
5. Final `output/FReD.xlsx` contains both FReD and COS data

The merge is done by column intersection, so only matching columns are included in both datasets.

## Disabling COS Integration

To disable COS merging:

```bash
# Option 1: Unset environment variable
unset ENABLE_COS_MERGE

# Option 2: Set to FALSE
export ENABLE_COS_MERGE=FALSE

# Option 3: Edit .env and change ENABLE_COS_MERGE=FALSE
```

The FReD pipeline will skip COS data merging and run with only the main FReD dataset.

## Removing COS Integration

If you no longer need COS integration, you can:

1. **Disable** the feature by setting `ENABLE_COS_MERGE=FALSE`
2. **Archive** COS data files:
   ```bash
   mv cos_integration/ archive/cos_integration_old/
   ```
3. **Remove** the conditional block from `pipelines/fred/prepare_fred.qmd` (the section labeled "COS Integration")

## Technical Details

### Column Matching

The COS data and FReD data are merged on matching column names. The merge happens like this:

```r
common_cols <- intersect(names(fred_raw), names(cos_data))
fred_raw <- bind_rows(
  fred_raw %>% select(all_of(common_cols)),
  cos_data %>% select(all_of(common_cols))
)
```

This ensures that columns with different names are not included, preventing data loss or misalignment.

### Data Consistency

After merging, all rows from both datasets are:
1. Cleaned using `clean_fred_data()`
2. Validated using data validation checks
3. Augmented with author overlap and references
4. Saved to the same output file

This ensures consistent processing regardless of whether COS data is included.

## Troubleshooting

### COS data not being merged

Check that:
1. `ENABLE_COS_MERGE` is set to `TRUE`
2. The file `cos_integration/cos_test_set_phase1_prepared.xlsx` exists
3. You're running `pipelines/fred/prepare_fred.qmd` (not `prepare_flora.qmd`)

View the pipeline output to see if the COS section ran.

### Column mismatch errors

If you see errors about column names not matching:
1. Check that COS data was prepared with `prepare_cos_data.R`
2. Compare column names in both datasets
3. May need to update `prepare_cos_data.R` to match FReD column structure

### Missing data after merge

If COS data is present but columns are missing:
- This is normal - only columns present in both datasets are kept
- Check the pipeline output for which columns were common
